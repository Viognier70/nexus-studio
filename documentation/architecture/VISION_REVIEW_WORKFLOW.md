# Vision Review Workflow

**Status:** Living process document for Phase IV.
**Audience:** Vision Owner + Claude Code.
**Time budget per review:** 5–15 minutes per district.

Every district cycle centres on the Vision Owner review. This document standardises the workflow so every review compares apples-to-apples.

## Preparation (Claude Code, one-time per district)

Before the first review, the following must exist:

1. `documentation/districts/<id>/README.md` — auto-generated, inventory current.
2. `reports/shadow-map/*.svg` — regenerated by `node scripts/shadow-map.mjs`.
3. Dev server on `localhost:5173` (or `5174`).
4. Camera preset suggestions in the district's `README.md` (Overview / Village / District / Close street). Suggestions can be refined by the Vision Owner during the first review.

## Review checklist

Walk the checklist below in order. Any 🔴 or 🟠 finding pauses the district; log to `KNOWN_ISSUES.md` before proceeding.

### 1 · Position (fast fail)
- Every landmark is visible at its expected map position.
- No mirrored geometry (compare to shadow-map SVG).
- No floating buildings (visible gap between wall and terrain).
- No buildings on top of roads.

### 2 · Roads
- Every named street visible in this district's Google Maps view is visible on localhost.
- Hälleforsvägen dominates its corridor.
- Prästgatan reads as a village street (not a residential alley).
- Intersections stack without visible gaps.

### 3 · Buildings — massing
- Building footprints match Google Maps footprints.
- Building heights look plausible for their kind (2–3 storeys for house, 3–5 for apartments).
- Multi-wing buildings render as connected volumes (Kärnhuset, Gästgivaregården).

### 4 · Buildings — facade
- Windows sit ABOVE the plinth on the ground floor.
- Windows sit BELOW the roof line on the top floor.
- Doors stand grounded on their step, attached to (not embedded in) the wall.
- Roof eaves project past the walls by ~0.35 m (except industrial parapets).

### 5 · Landmarks — recognition
- Church tower recognisable from village view.
- Torget reads as a plaza, not a road.
- INGO recognisable as a fuel station canopy.
- Tempo recognisable as a small grocery.
- Kärnhuset + Måltidens Hus recognisable as institutional buildings on Campus.

### 6 · Vegetation
- No trees inside buildings.
- No trees on roads.
- No trees on water.
- Forest edge feels natural (no hard boundary).

### 7 · Overall recognition
- Would a resident of Grythyttan recognise this district without the labels?

## Recording findings

For each defect, add a row to `documentation/districts/<id>/KNOWN_ISSUES.md`:

```markdown
| Severity | View | Description | Reference |
|----------|------|-------------|-----------|
| 🔴 Critical | Kvarteret view over Torget | Windows on Gästgivaregården are two storeys too high | Google Maps @59.7053,14.5390 |
```

Severity ladder:
- 🔴 **Critical** — blocks approval; must be fixed before freeze.
- 🟠 **High** — blocks approval unless documented waiver.
- 🟡 **Medium** — resolve in the current district cycle if time permits.
- ⚪ **Low** — track for a future cycle; not a blocker.
- 🟣 **Approximate** — known-limited by upstream data; documented in `APPROXIMATION_REGISTER.md`.

## Adding a verdict

After the checklist walk, add a row to `documentation/districts/<id>/REVIEWS.md`:

```markdown
| 2026-08-01 | Vision Owner | Rework | 3 High defects logged; see KNOWN_ISSUES rows 4–6 |
```

Valid verdicts:
- **Rework** — fix the logged defects and re-review.
- **Approved with waivers** — approve despite some 🟠 items, waivers cited in the row.
- **Approved** — no waivers, ready for freeze.
- **Approved for Freeze** — final freeze verdict (see `DISTRICT_FREEZE_GUIDE.md`).

## Camera preset conventions

Each district's `README.md` will accrue Vision-Owner-supplied camera positions over the first review cycle. Store them as:

```markdown
## Recommended camera positions

### Overview
- world position: (0, 500, 0)
- pitch: 32°
- yaw: -0.35
- purpose: whole district in one frame

### Village
- world position: (12, 200, 0)
- pitch: 40°
- yaw: 0.0
- purpose: primary Vision Owner review shot
```

Every future review must use the same positions. This is what makes side-by-side diffing possible.

## Post-review actions

If the verdict is **Rework**:
1. Claude Code fixes each Critical / High defect systemically.
2. Rerun `node scripts/parity-check.mjs && node scripts/validate-world.mjs`.
3. Rebuild and re-notify Vision Owner.

If the verdict is **Approved for Freeze**:
1. Follow `DISTRICT_FREEZE_GUIDE.md`.
